# AI Agent Context: Shopify Headless Storefront

This document serves as an architectural overview and technical reference for AI agents working on this project. It outlines the technology stack, project structure, conventions, and key libraries to ensure consistency when modifying or adding code.

## 1. Tech Stack Overview

- **Framework:** Next.js 16.1.6 (App Router)
- **Package Manager:** bun
- **UI/Components:** React 19, Radix UI primitives, shadcn/ui components
- **Styling:** Tailwind CSS v4, `clsx`, `tailwind-merge`, `class-variance-authority`
- **Animations:** Framer Motion (`framer-motion`), `tw-animate-css`
- **State Management:** Zustand (for global client state like Cart), React Query (for data fetching/caching)
- **Forms:** React Hook Form
- **Icons:** Lucide React (`lucide-react`), Radix UI Icons
- **E-commerce:** `@shopify/storefront-api-client` (Custom headless implementation, _not_ utilizing full Hydrogen framework)

## 2. Directory Structure (`/src`)

- `/app`: Next.js App Router. Contains page components (`page.tsx`), layouts (`layout.tsx`), and API routes (`api/`).
  - `/api`: Backend proxy routes for interacting with Shopify (e.g., `/api/cart`, `/api/auth`, `/api/checkout`, `/api/products`). This hides API keys from the client.
- `/components`:
  - `/ui`: Reusable UI components (typically generated by shadcn/ui).
  - `/cart`: Cart-related components (e.g., `cart-drawer.tsx`).
  - `/home`: Homepage specific sections (`hero.tsx`, `value-props.tsx`, etc.).
  - `/layout`: Global layout components (`navbar.tsx`, `footer.tsx`).
- `/lib`: Utility functions and core business logic.
  - `shopify.ts`: The core Shopify Storefront API client configuration (`publicShopifyClient`, `privateShopifyClient`).
  - `cartStore.ts`: Global Zustand store for managing the shopping cart.
  - `/cart`, `/customerAuth`: Domain-specific utility functions.
- `/types`: Global TypeScript definitions for Shopify models (`productTypes.ts`, `cartTypes.ts`, etc.).

## 3. Shopify Integration Strategy

- **API Client:** The project uses `@shopify/storefront-api-client` rather than `@shopify/hydrogen-react` for core data fetching.
- **Clients:**
  - `publicShopifyClient`: Uses public access token for reading products/collections.
  - `privateShopifyClient`: Uses private access token for cart/checkout operations.
- **Fetch wrapper:** Always use `shopifyFetch` or `shopifyCheckoutFetch` from `/src/lib/shopify.ts` when making Storefront API GraphQL calls. This handles error unwrapping natively.
- **Data flow:** To prevent leaking tokens, client components should typically fetch from local `/api/*` routes, which in turn use the Shopify clients to communicate with Shopify.

## 4. State Management Conventions

- **Global Client State (Cart):** Handled via `zustand` in `/src/lib/cartStore.ts`. It includes middleware for persistence (`hydratePersistentCart`, `syncPersistentCart`).
- **Data Fetching:** When fetching data on the client side, prefer using `@tanstack/react-query` to manage loading states, caching, and re-fetching.
- **Server State:** Use Next.js Server Components and standard `fetch` caching mechanisms when data is requested server-side.

## 5. Styling Conventions

- All styling is done via Tailwind CSS utility classes.
- Dynamic classes should be constructed using the `cn` utility (typically found in `src/lib/utils.ts` returning `twMerge(clsx(inputs))`) to handle overriding Tailwind classes properly.
- If creating UI components with variants, use `cva` (class-variance-authority).

## 6. Coding Standards for AI Agents

1. **TypeScript:** Strictly type all function parameters, returns, and component props. Use interfaces located in `/src/types/` whenever possible.
2. **Server vs. Client Components:**
   - Default to Server Components (`async function MyComponent`).
   - Add `"use client";` at the top of the file _only_ when interactivity (hooks, event listeners) is required.
3. **Imports:** Use absolute path aliases (`@/components/...`, `@/lib/...`) instead of relative paths (`../../`).

**_Note for Agents:_** Always read `src/lib/shopify.ts` and `src/lib/cartStore.ts` to understand existing ecommerce paradigms before implementing new Shopify features.

## 7. Naming Conventions & Routing

- **File Names:** All component, utility, and routing files must use lowercase with dashes (`kebab-case`) (e.g., `cart-drawer.tsx`, `value-props.tsx`).
- **Component Exports:** Use PascalCase for standard React component function names (e.g., `export function CartDrawer()`).
- **Routing:** Use standard Next.js App Router dynamic routing conventions (e.g., `/src/app/products/[handle]/page.tsx`).

## 8. Environment Variables & Security

- Public variables must be prefixed with `NEXT_PUBLIC_` (e.g., `NEXT_PUBLIC_SHOPIFY_STORE_DOMAIN`).
- **CRITICAL:** The `NEXT_PRIVATE_SHOPIFY_STOREFRONT_ACCESS_TOKEN` must **never** be imported or used in any file that has `"use client"` or lives outside the `/api` directory.
- All environment variables should be defined in `.env.local` locally and matching counterparts in Vercel/production.

## 9. Performance & SEO Optimizations

- **Images:** NEVER use standard `<img>` tags. Always use Next.js `<Image />` imported from `next/image` to utilize Shopify's CDN loader and prevent layout shifts.
- **Links:** Always use `<Link>` from `next/link` for internal routing to maintain App Router state and prefetching.
- **Client Bundles:** Keep Zustand stores lean. Use dynamic imports (`next/dynamic`) for heavy, non-critical components that sit below the fold.

## 10. Error Handling Protocols

- **API layer:** Ensure `shopifyFetch` catches GraphQL errors, unwraps them, and throws a standard JavaScript `Error`.
- **Component layer:** Catch errors gracefully and present them to the user via toast notifications (shadcn/ui toast or sonner) rather than throwing unhandled runtime exceptions.

## 11. SEO Constraints

- AI agents generating new pages must include exported Next.js `metadata` or `generateMetadata` functions containing `title`, `description`, and OpenGraph tags to ensure products show up perfectly on social media and Google.

## 12. Advanced Feature Architecture Documentation

- **Custom Reviews System (Local SQLite):**
  - **Database:** Uses `better-sqlite3` strictly in server environments to store text reviews in a `.data/reviews.db` file. This avoids filesystem race conditions and stateless deployment wipes during dev.
  - **Endpoints:** The `src/app/api/products/[handle]/reviews/route.ts` manages SQL read/writes.
  - **Hybrid UI Math:** The frontend (`app/products/[handle]/page.tsx`) queries the Shopify Storefront API for the baseline `reviews.rating` metafield, then dynamically merges it with the local SQLite data to compute accurate real-time review counts.

- **Predictive Search Engine:**
  - Implemented in `Navbar` (`navbar.tsx`), debouncing text input and querying `/api/search/predictive`.
  - Supports image thumbnail injections using Next.js `<Image>` preconfigured to allow `cdn.shopify.com` optimization.

- **In-Cart Upsells and Cross-Sells:**
  - Integrated directly into `cart-drawer.tsx` using `@tanstack/react-query`.
  - Driven by the Storefront API `productRecommendations` query (Intent: `RELATED`), injecting a visually scrollable recommendation carousel below the active cart items.

- **Dark / Light Mode Theme Toggle:**
  - Utilizes `next-themes` via `src/components/theme-provider.tsx`.
  - Wrapped around the router in `layout.tsx` (using `suppressHydrationWarning` on the `<html>` root specifically to prevent React dom mismatch exceptions).
  - Toggled efficiently via the `lucide-react` animated `<ThemeToggle />` component in the Navbar.
